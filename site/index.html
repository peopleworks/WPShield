M1 and M2 are loopback-only. The gateway validates at startup that every listener and every destination is a loopback address, and refuses to start otherwise. The rules described on this page now run on gateway traffic, but only for multipart/form-data: urlencoded forms, JSON, XML-RPC and application/octet-stream uploads stream through uninspected, and archive contents are never opened.

Do not place WPShield in front of a live WordPress site, and do not replace your IIS bindings on ports 80 and 443. Production activation is gated behind M1 to M6 validation and a controlled M7 rollout. The status table below says exactly what works today.

M1 y M2 son exclusivamente de loopback. El gateway valida al iniciar que cada listener y cada destino sean direcciones de loopback, y se niega a arrancar si no lo son. Las reglas descritas en esta página ya se ejecutan sobre el tráfico del gateway, pero solo para multipart/form-data: los formularios urlencoded, JSON, XML-RPC y las cargas application/octet-stream pasan sin inspeccionar, y el contenido de los archivos comprimidos nunca se abre.

No coloques WPShield delante de un sitio WordPress en producción, ni reemplaces tus enlaces de IIS en los puertos 80 y 443. La activación en producción está condicionada a completar de M1 a M6 y a un despliegue controlado en M7. La tabla de estado de más abajo dice exactamente qué funciona hoy.

A firewall written for Linux hosting looks for PHP. On Windows Server that is the wrong half of the attack surface. web.config is remote code execution on IIS with no script uploaded at all; .aspx and .ashx files run as the application pool identity; and Windows strips the trailing dot from shell.php. on the way to disk, so the name that was inspected is not the name that lands.

Un firewall escrito para hosting Linux busca PHP. Sobre Windows Server esa es la mitad equivocada de la superficie de ataque. web.config es ejecución remota de código en IIS sin subir ningún script; los archivos .aspx y .ashx se ejecutan con la identidad del grupo de aplicaciones; y Windows elimina el punto final de shell.php. camino al disco, de modo que el nombre inspeccionado no es el nombre que aterriza.

What a Linux-shaped WAF misses Lo que una WAF pensada para Linux no ve

IIS executes more than PHP.

IIS ejecuta mucho más que PHP.

The rules a WordPress firewall inherits from Linux hosting are about PHP, because on Linux the web server executes almost nothing on its own. On Windows Server the web server is a general application host. Three consequences follow, and all three are things WPShield exists to cover.

Las reglas que un firewall de WordPress hereda del hosting Linux tratan sobre PHP, porque en Linux el servidor web casi no ejecuta nada por sí mismo. En Windows Server el servidor web es un host de aplicaciones general. De ahí se siguen tres consecuencias, y las tres son exactamente lo que WPShield existe para cubrir.

IIS-CONFIG-001 · 100

A configuration file is a program

Un archivo de configuración es un programa

IIS reads web.config from every directory it serves and applies it to that directory and everything under it. Writing one into wp-content/uploads registers a handler mapping that executes files of the attacker's choosing, re-enables script execution the operator disabled, or relaxes authorization for the directory.

No script is uploaded. The file write is the execution. This carries the highest score any single WPShield rule assigns, and the project expects no false positives from it: no WordPress workflow uploads a web.config through a request body.

IIS lee web.config en cada directorio que sirve y lo aplica a ese directorio y a todo lo que cuelga de él. Escribir uno en wp-content/uploads registra un mapeo de handler que ejecuta los archivos que el atacante elija, reactiva la ejecución de scripts que el operador deshabilitó, o relaja la autorización del directorio.

No se sube ningún script. La escritura del archivo es la ejecución. Esta es la puntuación más alta que asigna una sola regla de WPShield, y el proyecto no espera falsos positivos: ningún flujo de WordPress sube un web.config en el cuerpo de una solicitud.

IIS-UPLOAD-001 · 90 / 50

Handlers that are not PHP

Handlers que no son PHP

.aspx, .ashx, .asmx and .ascx run as the application pool identity, which is a strictly larger capability than a PHP shell. The rule also covers .asp, .axd, .cshtml, .vbhtml, .razor, .svc, .soap, .rem, .asax and .master.

A WordPress site has no legitimate reason to accept any of them through an upload endpoint. This is the gap the project exists to close.

.aspx, .ashx, .asmx y .ascx se ejecutan con la identidad del grupo de aplicaciones, que es una capacidad estrictamente mayor que la de un shell en PHP. La regla también cubre .asp, .axd, .cshtml, .vbhtml, .razor, .svc, .soap, .rem, .asax y .master.

Un sitio WordPress no tiene ninguna razón legítima para aceptar ninguno de ellos por un endpoint de carga. Esta es la brecha que el proyecto existe para cerrar.

FILE-NAME-001 · 60

The name that reaches disk

El nombre que llega al disco

Windows collapses trailing dots and spaces, and NTFS drops the ::$DATA alternate data stream suffix. shell.php. arrives as shell.php. A check that reads the client's string is checking a name that will not exist.

So no WPShield rule ever sees the raw value. Every rule matches a Windows-aware normalization of it, and each anomaly that had to be removed to produce it becomes evidence in its own right.

Windows elimina los puntos y espacios finales, y NTFS descarta el sufijo de flujo de datos alternativo ::$DATA. shell.php. llega como shell.php. Una comprobación que lee la cadena del cliente está comprobando un nombre que no va a existir.

Por eso ninguna regla de WPShield ve el valor original. Todas evalúan una normalización consciente de Windows, y cada anomalía que hubo que eliminar para obtenerla se convierte en evidencia por derecho propio.

It is not enough to rely on sanitize_file_name(). The vulnerable plugin endpoints that cause upload incidents are precisely the ones that write files without calling it — which is the reason WPShield inspects the request rather than trusting what WordPress will do with it.
No basta con confiar en sanitize_file_name(). Los endpoints vulnerables de plugins que provocan incidentes de carga son precisamente los que escriben archivos sin llamarla, y esa es la razón por la que WPShield inspecciona la solicitud en lugar de confiar en lo que WordPress hará con ella.

Findings, not verdicts Hallazgos, no veredictos

A stable rule ID, a score,
and the evidence that produced it.

Un ID de regla estable, una puntuación
y la evidencia que la produjo.

A rule returns a record, not a verdict: the rule ID, the score it contributed, a message key, and bounded evidence. Rule IDs are never translated, so an operator reading Spanish and a maintainer reading English are looking at the same identifier. Only the message key is localized.

Una regla devuelve un registro, no un veredicto: el ID de la regla, la puntuación que aportó, una clave de mensaje y evidencia acotada. Los IDs de regla no se traducen nunca, así que un operador que lee en español y un mantenedor que lee en inglés están mirando el mismo identificador. Solo se localiza la clave de mensaje.

In Monitor the action is Observe at any score. It is never Block. That is the point of a default mode: an operator can run WPShield against real traffic, read what it would have done, and only then decide. Turning on Block is a per-site decision made deliberately, never a consequence of installing anything.
En Monitor la acción es Observe con cualquier puntuación. Nunca es Block. Ese es el sentido de un modo por defecto: un operador puede ejecutar WPShield contra tráfico real, leer lo que habría hecho y solo entonces decidir. Activar Block es una decisión deliberada y por sitio, nunca una consecuencia de instalar nada.

Multi-site, fail closed Multisitio, cierre por defecto

Every hostname is assigned.
There is no default backend.

Cada nombre de host está asignado.
No hay backend por defecto.

Several WordPress sites usually share one Windows Server. A gateway with a fallback destination turns a host-header trick into a route to somebody else's site, so WPShield has none: a host that is not in the table is rejected, and the request never reaches a backend.

Varios sitios WordPress suelen compartir un mismo Windows Server. Un gateway con un destino de reserva convierte un truco de cabecera Host en una ruta hacia el sitio de otro, así que WPShield no tiene ninguno: un host que no esté en la tabla se rechaza, y la solicitud nunca llega a un backend.

HTTP 421

Unknown host, no backend

Host desconocido, sin backend

A request whose Host matches no configured site is answered with 421 Misdirected Request and a request identifier. Nothing is forwarded, and the log line records the host, method and path — never the query string.

Una solicitud cuyo Host no coincide con ningún sitio configurado recibe 421 Misdirected Request y un identificador de solicitud. No se reenvía nada, y la línea de registro anota el host, el método y la ruta, nunca la cadena de consulta.

Startup validationValidación al arrancar

Mistakes fail at start, not at runtime

Los errores fallan al arrancar, no en ejecución

A hostname assigned to two sites, a listener that is not loopback, a destination that is not loopback, or a destination that points back at the gateway: each of these stops the process from starting. The gateway then prints the site table it actually resolved, because JSON configuration providers merge arrays element by element and an operator overlay with fewer sites leaves the shipped examples active.

Un nombre de host asignado a dos sitios, un listener que no es loopback, un destino que no es loopback, o un destino que apunta de vuelta al gateway: cada uno de ellos impide que el proceso arranque. Después el gateway imprime la tabla de sitios que realmente resolvió, porque los proveedores de configuración JSON fusionan los arreglos elemento a elemento y una superposición del operador con menos sitios deja activos los ejemplos incluidos.

Forwarding headersCabeceras de reenvío

Replaced, not trimmed

Reemplazadas, no recortadas

Every X-Forwarded-* variant is removed by prefix, along with Forwarded, X-Real-IP, X-Client-IP, True-Client-IP, CF-Connecting-IP and the Azure client-address headers. X-Original-URL and X-Rewrite-URL go too: IIS URL Rewrite treats them as the effective request path, which is an established authentication-bypass vector. WPShield then writes its own values from the actual connection.

Cada variante X-Forwarded-* se elimina por prefijo, junto con Forwarded, X-Real-IP, X-Client-IP, True-Client-IP, CF-Connecting-IP y las cabeceras de dirección de cliente de Azure. X-Original-URL y X-Rewrite-URL también: IIS URL Rewrite las trata como la ruta efectiva de la solicitud, que es un vector conocido de elusión de autenticación. Después WPShield escribe sus propios valores a partir de la conexión real.

HTTP 413

Bounded bodies

Cuerpos acotados

6 MiB by default, with a hard configuration ceiling of 64 MiB. A declared Content-Length over the limit is rejected before anything is forwarded; a body of unknown length is counted while it streams and cut off at the same limit. Both answer 413.

6 MiB por defecto, con un techo fijo de configuración de 64 MiB. Un Content-Length declarado por encima del límite se rechaza antes de reenviar nada; un cuerpo de longitud desconocida se cuenta mientras se transmite y se corta en el mismo límite. Ambos responden 413.

Step by step Paso a paso

Eight steps, and two of them
take a live site down if you rush.

Ocho pasos, y dos de ellos tumban
un sitio en vivo si los apura.

This is the order that works, written after running it against a Windows Server hosting sixty-six sites. Steps 1 to 6 change nothing an external visitor can see; step 7 is the one that touches live traffic, and step 8 is where you find out whether the rules fit your site. Every command below reports what it is about to do before doing it.

Este es el orden que funciona, escrito después de ejecutarlo contra un Windows Server con sesenta y seis sitios. Los pasos 1 a 6 no cambian nada que un visitante externo pueda ver; el paso 7 es el que toca el tráfico en vivo, y el 8 es donde usted descubre si las reglas encajan con su sitio. Cada comando reporta lo que va a hacer antes de hacerlo.

  1. Publish on a build machine, never on the server

    Publique en una máquina de compilación, nunca en el servidor

    Publish-WPShield.ps1 needs the .NET SDK. A web server does not have one and should not get one. It produces a self-contained win-x64 directory, a zip and a SHA-256, so the transport can be verified rather than trusted.

    Publish-WPShield.ps1 necesita el SDK de .NET. Un servidor web no lo tiene y no debería tenerlo. Produce un directorio autocontenido win-x64, un zip y un SHA-256, para que el transporte se verifique en vez de confiarse.

    build machine 
    PS> .\scripts\Publish-WPShield.ps1

  2. Copy two things across, not one

    Copie dos cosas al servidor, no una

    The archive holds the gateway and nothing else. The scripts are not inside it, so scripts\*.ps1 travels separately — and it travels every time, not only the first.

    El archivo lleva el gateway y nada más. Los scripts no van dentro, así que scripts\*.ps1 viaja aparte — y viaja cada vez, no solo la primera.

    Stale scripts are the quiet failure here. An older installer has none of the checks the current one has: it will not refuse a path inside a web root, it will not write the log directory into the configuration, and the preflight will not report an installation IIS is already serving. If the preflight prints no PRE-019, you copied the old ones.
    Los scripts viejos son el fallo silencioso de este paso. Un instalador anterior no tiene ninguna de las comprobaciones del actual: no rechaza una ruta dentro de una raíz web, no escribe el directorio de registros en la configuración, y el preflight no reporta una instalación que IIS ya esté sirviendo. Si el preflight no imprime PRE-019, copió los viejos.

  3. Run the preflight and clear every blocker

    Corra el preflight y despeje todo bloqueador

    Nineteen checks, read-only, elevated. It changes no IIS setting, no binding, no rule, no service, no ACL. It exists because this traffic path has several ways to fail on the live site, at the moment the rewrite rule is enabled, with an error that does not say what is wrong.

    Diecinueve comprobaciones, de solo lectura, elevado. No cambia ningún ajuste de IIS, ni un binding, ni una regla, ni un servicio, ni una ACL. Existe porque esta ruta de tráfico tiene varias formas de fallar en el sitio en vivo, justo cuando se activa la regla de reescritura, con un error que no dice qué está mal.

    server 
    PS> .\Invoke-WPShieldPreflight.ps1

  Pass    PRE-007  ARR server-level proxy is enabled
  Pass    PRE-008  ARR preserves the client Host header
  Warn    PRE-018  Catch-all rewrite rules the WPShield rule must be ordered before
  Pass    PRE-019  Nothing of WPShield sits inside a directory IIS serves

  4. Install, with a dry run first

    Instale, con una pasada en seco primero

    The installer registers a service named WPShield and only ever that one, gives it the virtual account NT SERVICE\WPShield — no password stored anywhere — replaces the permissions on both directories, and writes the log path into the configuration the gateway actually reads. It touches nothing in IIS.

    El instalador registra un servicio llamado WPShield y jamás ningún otro, le da la cuenta virtual NT SERVICE\WPShield — sin contraseña guardada en ningún sitio —, reemplaza los permisos de ambos directorios y escribe la ruta de registros en la configuración que el gateway realmente lee. No toca nada de IIS.

    server, elevated 
    PS> .\Install-WPShield.ps1 -Path C:\staging\wpshield -WhatIf
PS> .\Install-WPShield.ps1 -Path C:\staging\wpshield

  identity: NT SERVICE\WPShield
  no unprivileged account can read either directory
    Read those last two lines back. An install that stops early can leave the service running as LocalSystem with both directories still inheriting their parents — and the summary above them will still have printed. Confirm it from outside: Get-CimInstance Win32_Service and look at StartName.
    Lea esas dos últimas líneas. Una instalación que se detiene a medias puede dejar el servicio corriendo como LocalSystem y ambos directorios heredando de sus padres — y el resumen de arriba se habrá impreso igual. Confírmelo por fuera: Get-CimInstance Win32_Service y mire StartName.

  5. Write the configuration, and declare every host

    Escriba la configuración, y declare todos los hosts

    appsettings.Local.json holds your real hostnames, so it stays on the server and out of the repository. The preflight prints one filled in from what it found.

    appsettings.Local.json lleva sus nombres de host reales, así que se queda en el servidor y fuera del repositorio. El preflight imprime uno relleno con lo que encontró.

    appsettings.Local.json 
    {
  "Gateway": { "TrustedProxies": [ "127.0.0.1", "::1" ] },
  "Sites": [
    {
      "Id": "site-one",
      "Hosts": [ "wordpress-one.example", "www.wordpress-one.example" ],
      "Destination": "http://127.0.0.1:8081",
      "Mode": "Monitor"
    }
  ]
}
    Two traps live in this file. Destination is the private loopback binding you added for this — never 80 or 443, which the gateway now refuses outright. And JSON arrays merge element by element, so an overlay declaring fewer sites or fewer hosts leaves the shipped .example entries active and routable; the gateway refuses to start when it sees real hostnames mixed with placeholders.
    Dos trampas viven en este archivo. Destination es el enlace de loopback privado que usted añadió para esto — nunca el 80 ni el 443, que el gateway ahora rechaza de plano. Y los arreglos JSON se fusionan elemento por elemento, así que una superposición con menos sitios o menos hosts deja activas y enrutables las entradas .example publicadas; el gateway se niega a arrancar si ve hosts reales mezclados con marcadores.

  6. Prove it forwards — before touching IIS

    Demuestre que reenvía — antes de tocar IIS

    This is the step that separates the gateway is broken from IIS is not sending it anything, and skipping it means debugging both at once on a live site.

    Este es el paso que separa el gateway está roto de IIS no le está mandando nada, y saltárselo significa depurar los dos a la vez sobre un sitio en vivo.

    server 
    PS> Start-Service WPShield
PS> curl.exe -i -H "Host: wordpress-one.example" http://127.0.0.1:10000/

  HTTP/1.1 200 OK
  X-WPShield-Request-ID: 0980620a0c18458498620581088af67c

    That header is the proof. It means WPShield resolved the host, forwarded to the private binding, and stamped the loop guard. Check the log too: it must say one Now listening on line and no error.

    Esa cabecera es la prueba. Significa que WPShield resolvió el host, reenvió al enlace privado y estampó el guardia de bucle. Mire también el log: debe decir una sola línea Now listening on y ningún error.

  7. IIS. Three changes, in this order.

    IIS. Tres cambios, en este orden.

    This is the step that goes wrong, and doing the second before the first returns 500 for the whole site. Start with a site you can afford to break.

    Este es el paso que sale mal, y hacer el segundo antes que el primero devuelve 500 en todo el sitio. Empiece por un sitio que pueda permitirse romper.

    a

    Allow the server variable

    Permita la variable de servidor

    IIS Manager, the site, URL Rewrite, View Server Variables, add HTTP_X_FORWARDED_PROTO. URL Rewrite refuses to set an HTTP_ variable that is not on this list, and the symptom is a 500.

    IIS Manager, el sitio, URL Rewrite, View Server Variables, añada HTTP_X_FORWARDED_PROTO. URL Rewrite se niega a establecer una variable HTTP_ que no esté en esa lista, y el síntoma es un 500.

    b

    The rule, ordered first

    La regla, en primer lugar

    The WPShield rule must sit above the WordPress permalink rule. Below it, either the rule never runs or it runs against the already-rewritten URL — and both look like a site working perfectly.

    La regla de WPShield debe ir encima de la de enlaces permanentes de WordPress. Debajo, o no se ejecuta nunca o se ejecuta contra la URL ya reescrita — y las dos cosas se ven como un sitio funcionando perfecto.

    c

    Let WordPress read it

    Que WordPress lo lea

    WordPress on IIS reads $_SERVER['HTTPS'], which IIS derives from the real connection — plain HTTP on the private binding. Without translating the header in wp-config.php, every page redirects to HTTPS forever.

    WordPress sobre IIS lee $_SERVER['HTTPS'], que IIS deriva de la conexión real — HTTP plano en el enlace privado. Sin traducir la cabecera en wp-config.php, cada página redirige a HTTPS para siempre.

    web.config — first rule in the list 
    <rule name="WPShield" patternSyntax="ECMAScript" stopProcessing="true">
  <match url=".*" />
  <conditions>
    <add input="{HTTP_X_WPSHIELD_REQUEST_ID}" pattern="^$" />
  </conditions>
  <serverVariables>
    <set name="HTTP_X_FORWARDED_PROTO" value="https" />
  </serverVariables>
  <action type="Rewrite" url="http://127.0.0.1:10000/{R:0}" />
</rule>
    Know the rollback before you save. Once the rule is live, stopping the service does not bypass WPShield — it takes the site down, because IIS keeps forwarding to a port with nothing behind it. The control that puts the site back is disabling the rewrite rule. The condition above is the loop guard: WPShield stamps that header on everything it forwards and strips any inbound copy, so the request coming back does not match the rule and a visitor cannot forge it to skip inspection. Both halves are load-bearing.
    Conozca la vuelta atrás antes de guardar. Con la regla activa, detener el servicio no esquiva WPShield — tumba el sitio, porque IIS sigue reenviando a un puerto sin nada detrás. El control que devuelve el sitio es deshabilitar la regla de reescritura. La condición de arriba es el guardia de bucle: WPShield estampa esa cabecera en todo lo que reenvía y borra cualquier copia entrante, así que la petición de vuelta no coincide con la regla y un visitante no puede falsificarla para saltarse la inspección. Las dos mitades cargan peso.

  8. Watch Monitor before you touch Block

    Observe en Monitor antes de tocar Block

    In Monitor the gateway forwards everything and refuses nothing, so the log is the only artefact it produces. Read it for days, not minutes: what you are looking for is the false positive that would have refused a real visitor.

    En Monitor el gateway reenvía todo y no rechaza nada, así que el log es lo único que produce. Léalo durante días, no minutos: lo que busca es el falso positivo que habría rechazado a un visitante real.

    An empty log with real traffic is a finding, not a quiet night. It means the rule is not live, or it is ordered below the permalink rule — and in that second case the site works perfectly while nothing is inspected at all.
    Un log vacío con tráfico real es un hallazgo, no una noche tranquila. Significa que la regla no está activa, o que quedó debajo de la de enlaces permanentes — y en ese segundo caso el sitio funciona perfecto mientras no se inspecciona nada.

When it goes wrong, it goes wrong in four ways

Cuando sale mal, sale mal de cuatro formas

Four failure modes, and the first move for each.
Symptom Cause First move
421 The Host is not in your site table, or ARR is not preserving it. Disable the rule. Compare Hosts against the site's bindings.
ERR_TOO_MANY_REDIRECTS WordPress sees plain HTTP behind an HTTPS site. One of the three pieces in step 7 is missing. Disable the rule. Check wp-config.php first — it is the one most often skipped.
500.19 Malformed web.config, or a server variable set without being allowed. Restore the backup you took, then do step 7a before 7b.
Nothing in the log The site works and nothing is inspected. The rule is inactive, or ordered below the catch-all. This is the silent one. Check the rule order before concluding anything.
Cuatro modos de fallo, y el primer movimiento para cada uno.
Síntoma Causa Primer movimiento
421 El Host no está en su tabla de sitios, o ARR no lo está preservando. Deshabilite la regla. Compare Hosts con los bindings del sitio.
ERR_TOO_MANY_REDIRECTS WordPress ve HTTP plano detrás de un sitio HTTPS. Falta una de las tres piezas del paso 7. Deshabilite la regla. Revise wp-config.php primero — es la que más se olvida.
500.19 web.config mal formado, o una variable de servidor puesta sin permitirla. Restaure el respaldo, y haga el paso 7a antes que el 7b.
